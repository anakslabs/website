How these five numbers were counted

Every row was measured the same way on both pages: we look at each page exactly as it first arrives to a search engine — before anything loads or runs — and count what is actually there. In plain terms:

Section titles Google can actually read
Of all the section titles on the page, how many arrive as real written text.
Section titles that are pictures
Titles a visitor sees perfectly but which arrive as an image with no text behind it — in the before build, that includes the headline itself.
The question-and-answer format
Whether the page answers patient questions in the structured form search engines recognise and can quote.
Summaries written for machines
Whether the page carries a machine-readable summary of the practice — hours, services, answers — that a search engine can pick up directly.
How much the search engine receives
The words that arrive with the page itself, compared with everything a patient can eventually read. In the before build, the six services are only added after the page loads — a patient swipes through them, but they were never handed to the machine.

One thing to be fair about. 878 of the after build's 2,629 characters are the four patient questions and their answers — content the before build never carried in any form. Set those aside and it is still 1,751 characters against 716: the same services, the same hours, the same headline, and nearly two and a half times as much of it reaching the machine.

Why it happens

Nothing in the before build is broken. That is the problem.

It loads fast, it reads well, it works on a phone. Every one of its problems is invisible to the person who owns it, because every one of them is in the code underneath — and that code is the only part a machine ever sees.

  • The headline is a picture

    Custom type, exact spacing, perfectly on brand — and set into the page as an image with nothing written behind it. A patient reads it. A search engine receives a title with nothing in it. This is not the most common fault we measured in the US, but where it happens it removes the single most important sentence on the page.

  • The services arrive after the page does

    Six services, one at a time, in a slider a patient swipes through. The words live in a script and are put into the page only once it has loaded. What the patient swipes through, the search engine was never handed.

  • Nothing answers a question

    Cost, how long it takes, whether you can be seen today, where to park. The before build never answers any of them, so nothing can quote it on any of them. In every group of clinic sites we measured, at least two in three never answer a patient question on the page.

  • Nothing tells a machine what the practice does

    No questions answered in the format search engines recognise, no summary of the practice, no opening hours anywhere a machine can pick them up. Organised to a patient, one undifferentiated block of text to a machine.

Two of the five patterns we describe on the product page are not reproduced here — answers locked inside a PDF, and having no way to measure what visitors do. Those need a file and an audience, not a change to the code, so a specimen cannot honestly show them.
